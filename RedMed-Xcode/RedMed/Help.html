6. Where Your Data Is Held

Your profile is held on your own device and, if you write one, on your bracelet’s NFC chip. It is not uploaded, synchronized, or backed up to any RedMed server, because we do not operate one. When somebody taps your band, nothing is fetched from us — the card is rendered from what is on the chip.

On iOS the profile is stored in the device Keychain, which is encrypted by the device hardware. We store it with the WhenUnlockedThisDeviceOnly protection class, which means it is readable only while the device is unlocked and is excluded from iCloud and encrypted device backups — it does not sync to your other devices and does not travel with a restored backup.

7. The Bracelet Is Readable by Anyone

Your RedMed profile is written to a passive NXP NTAG216 HF NFC chip at 13.56 MHz (ISO 14443A Type 2, NDEF blank unlocked). That is a different radio band from Bluetooth (~2.4 GHz): the band is not paired over Bluetooth and has no battery, sensors, or radio of its own. Your phone powers it only for a moment during an intentional tap or write — the App does not keep an active RF session with the bracelet. It does not track you, monitor you, or record anything.

Anyone who deliberately taps the band can read the card. New writes use AES-GCM packing with a public client key shared by the iPhone app and the passerby page — that is obfuscation so the fragment is not casual plaintext JSON, not confidentiality against a responder (or anyone else) who opens the URL. EMS needs no app, no account, and no password. Treat the band as you would a printed medical ID card, and do not put anything on it that you would not accept a stranger reading. If you would rather not disclose a particular condition, leave it out. See also Security.

Location defaults on in Help → Settings. RedMed does not show an in-app location gate or suggestion banner. The first time Find Help needs GPS, iOS may show its own When-In-Use Allow dialog — that one system tap is required by Apple and cannot be skipped or auto-accepted by the App. Your device supplies location using GPS/GNSS, Wi‑Fi, and cellular signals as available.

RedMed is not Apple Emergency SOS via satellite, Apple Crash Detection, or any carrier satellite messaging service, and cannot start or control those radios. 4. On-Device Profile Storage

  • Profile fields persist in the iOS Keychain with WhenUnlockedThisDeviceOnly.
  • Readable only while the device is unlocked; excluded from iCloud and encrypted device backups.
  • Local history / vault files use FileProtectionType.complete and isExcludedFromBackup so they stay unreadable when the phone is locked or plugged into another computer, and are never copied to consumer iCloud backups.
  • Owner biometrics / device passcode gate edit, NFC write, app unlock, and the local history dashboard. Passerby tapper.html (band tap / EMT card) never prompts for Face ID, biometrics, passcode, login, or any authentication — tap-to-view opens the card immediately from #d=.
  • App-switcher snapshots are covered so live profile text is not cached to the system snapshot image.
  • Edit fields disable system autofill content types so medical text is not written into keyboard / autofill caches.
  • Clearing fields and saving overwrites the stored profile. Help → Erase all RedMed data (Face ID / passcode) deletes the Keychain profile and vault files on this iPhone; deleting the App also removes them. The physical band is not wiped remotely.

5. NFC Band (Readable by Design)

Passive NFC identification payloads use AES-GCM packing with a public client key shared by the iPhone app and tapper.html. That is packing / obfuscation so the fragment is not casual plaintext JSON — any phone that loads the card page can decrypt. A private key would defeat the EMS assist model (no account to view). Cloning a tag is like photocopying a wallet medical card. Casual walk-by distance will not fire the band; only a deliberate ~1–2″ antenna tap reads it. RedMed does not background-scan the band. The band stays passive — no battery (not AirTag / BLE). iOS Background Tag Reading can still open tapper.html later on a deliberate tap even when the phone is off or locked (owner or any passerby). Wrist + pocket is usually fine; phone pressed to the clasp can pop Safari. Writing the chip does not change that likelihood. Payment / POS terminals use a different protocol (EMV) and do not open the RedMed card. The card page renders #d= via textContent with length caps and phone sanitization. There is no RedMed profile server — fields stay on the device Keychain and, if written, in the band fragment.

6. Location

GPS starts only on Find Help (When-In-Use). Coordinates stay on-device for display to you / a dispatcher. We do not receive, log, or retain them. Location assist does not guarantee that 911 will be reached or that coordinates will be accurate. Do not log location.hash, NFC URLs, profile JSON, or PIN material in any tooling you add later.

7. Reporting Vulnerabilities

Open a private GitHub security advisory on Roooted1776/frisky for XSS in #d= rendering, Keychain / vault bypass, or owner-app unlock gate bypass. Or email help.RedMed@gmail.com. Do not file public issues with live API keys or real medical payloads. See root SECURITY.md.

8. Trust Root (On-Device)

There is no RedMed profile server. The trust root is the owner’s iPhone: Keychain for the profile blob, biometrics / passcode gates, RAM purge on background, vault file protection, and the passive band fragment if written. Treat main as the product source of truth for the app binary and bundled card shell.

9. Third-Party Keys

RedMed does not ship a Google Maps (or other) API key in the app bundle today, and does not call a RedMed backend. Never commit key material — **/google-api-key stays in .gitignore.

10. Dependencies

Almost no runtime deps (no npm, no CocoaPods). Do not add analytics or crash SDKs that phone home profile or location without an explicit product decision — that would change both the privacy posture and, if PHI were ever transmitted to a vendor under a covered-entity arrangement, the HIPAA analysis.
